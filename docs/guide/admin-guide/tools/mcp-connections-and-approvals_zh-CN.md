# MCP 连接与审批

本指南面向配置已保存 MCP 服务器、并管理其调用身份与审批的团队管理员和运维人员，介绍连接、OAuth、审批、资源、提示词以及实时资源订阅。字段级请求/响应说明见 [工具 API](../../api-reference/endpoints/tools.md#saved-mcp-server-protocol)。

## 已保存的服务器，而不是客户端凭据

已保存的 MCP 工具会把传输方式、URL/命令以及请求头/环境变量模板保存在工具定义中。Agent、工作流或工具面板使用该服务器时，后端会为当前身份解析连接，并且只注入工具声明的字段。调用方只选择**使用哪个身份**，绝不会提交 `mcp_config`、请求头或凭据值。响应和运行事件都不包含秘密值或渲染后的服务器配置。

原始的 `POST /tools/mcp/list-tools` 及管理端同类接口仅用于未保存定义的临时诊断，并计划从已保存工具对话框中移除。任何已经保存的配置都应使用已保存服务器接口（`/tools/{tool_id}/mcp/...`）。

## 身份类型

每个工具声明一种身份策略：

| 策略 | 含义 |
|------|------|
| `none` | 不需要外部身份；不接受连接 |
| `team_only` | 使用团队范围连接 |
| `personal_only` | 使用当前操作者的个人连接 |
| `selectable` | 默认使用当前调用用户的个人账号；编排可明确固定个人或团队连接 |

连接范围：

| 范围 | 所有者 | 说明 |
|------|--------|------|
| `user` | 个人用户 | 按团队隔离；仅所有者可交互使用 |
| `team` | 团队 | 共享账号；需要团队成员身份 |
| `site` | 站点管理员 | 全局账号；工具编辑者不能覆盖 |

需要身份却没有连接时，明确提示先配置账号或登录；连接需要重新授权时，提示重新连接，不回退到其他账号。

未固定连接的个人／可选身份工具，在交互调用和手动工作流运行时，按当前调用用户、消费团队和工具自动选择：优先使用默认连接，否则使用唯一未撤销的个人连接。多个连接且未设默认时，提示设置默认或明确固定连接。默认连接或唯一连接失效时，必须重新授权；不会借用其他用户、团队账号或其他团队的连接。MCP 子工具发现也使用同一个身份，避免需要登录的工具在模型调用前被静默跳过。

## 连接账号

用户可以在当前团队中自行准备和查看连接，无需编辑工具：打开头像菜单 →「设置」→「工具连接」。该页会列出你在当前团队下可用的全部连接，显示所属工具、账号标识、范围、是否为默认连接以及状态，并提供添加、设为默认、重新授权和删除操作。添加连接从选择工具开始，因此只列出接受身份的工具；声明字段和 OAuth 的处理方式与工具的连接管理一致。在应用内切换团队后列表随之变化；设置弹窗内不单独提供团队切换。

1. 打开工具的连接管理，选择范围（`personal` 或 `team`；`site` 仅管理员可用）。
2. 只填写工具声明的字段。值只写、加密存储；接口只返回字段名、可选的账号标签和秘密版本号。
3. 选择是否为该范围与服务的默认连接。
4. 通过 `config_set` / `config_remove` 轮换或删除秘密；携带 `expected_secret_version` 可避免覆盖并发修改。

撤销连接是终态操作。需要更换外部账号时请新建连接；审批绑定连接版本，旧审批不会自动迁移。

## MCP OAuth

如果服务器定义启用了 `mcp_config.oauth`，连接必须先完成授权：

1. `POST /tool-connections/{id}/oauth/start` 返回授权 URL 和一次性 state。需要客户端密钥时，密钥只写且要求工具写权限。
2. 浏览器完成提供方流程后回到精确允许的前端路径，回调完成代码交换。
3. `GET /tool-connections/{id}/oauth` 显示授权状态、scope 和过期时间，不返回令牌。
4. 断开连接会清除本地令牌并尽力撤销远端授权；远端失败会明确报告，但不会阻止本地撤销。

流程使用 PKCE S256、一次性 state、精确回调匹配、最小 scope 和 refresh 轮换。发现与令牌端点受集中 SSRF 策略约束，且必须使用 HTTPS。`invalid_grant` 会把连接标记为 `reauth_required`，需要重新发起授权。符合规范的提供方应可工作，但本平台不声明与任何特定第三方提供方已验证互通。

## 连接绑定与共享执行

个人／可选身份工具默认提供**自动（当前用户）**：不保存编排者的账号，每个运行用户使用自己的连接。编排者无需先配置账号才能添加工具；使用者在工具连接管理中添加账号或完成登录，有多个账号时设置默认连接。

编排明确选定具体连接，才表示**固定连接**，本身就是允许该定义使用该外部身份的授权，不需要单独的委托步骤。已认证的飞书和微信 Agent 对话可以自动使用调用者在 Agent 所属团队中的个人连接；团队账号仍需明确绑定。API Key、嵌入、旧版渠道和定时任务必须固定连接，不会自动采用其他用户的个人账号。

- 个人连接只能由所有者选择；管理员不能绑定他人的个人账号。
- 创建、更新、复制、恢复版本或从包导入 Agent/工作流时都会校验绑定。导入的包会移除环境相关的连接 ID，需要在目标团队重新选择。
- 只有固定连接时，绑定才属于该定义；任何有权运行该 Agent 或工作流的人（包括共享工作流、定时任务、API Key、渠道或嵌入）都会以已保存的账号执行。
- 每次执行都会重新检查连接存在、已启用、属于当前团队且与服务匹配。连接撤销或不可用时直接失败，绝不回退到其他账号。
- 调用方无法取得凭据：连接密钥保持只写，运行事件和接口响应都不会返回密钥。

更换固定身份需要重新选择连接。等待确认的调用始终绑定创建时的账号与连接版本，不能改用替换后的连接；后续调用需要重新获得调用者确认。修改个人默认账号不会改变该次执行绑定的身份或连接版本。

## 使用服务器能力

已保存的 MCP 服务器可以提供：

- **工具**：带参数调用；结果保留内容块、结构化内容和错误状态。
- **资源**：按 URI 列出与读取。资源文本和链接属于不可信上下文；后端不会自动下载链接。
- **资源模板**：单独列出；展开 URI 后读取。
- **提示词（Prompts）**：列出并按参数渲染。消息需要预览，不会自动成为系统指令。
- **补全**：在同一身份与审批边界下补全提示词或模板参数。
- **订阅**：为单个 URI 流式接收资源变更通知。

列表结果有上限，会报告 `truncated`/`truncation_reason`，并提供可续传的 `next_cursor`（页内截断除外）。列表获取和能力浏览器中的直接操作不触发工具执行审批；访问权限与连接身份检查仍然生效。

## 审批

工具编辑器中的**调用前需要确认**开关控制默认行为：开启时需要调用者确认，关闭时不需要；其他访问权限与安全检查仍然生效。MCP 单项规则可以继承默认设置，或明确要求／不要求确认。已有拒绝策略继续禁止调用，不会被静默转换：默认拒绝可主动替换为调用者确认，单项拒绝则保留到管理员明确修改该规则。审批只在工具定义上配置；站点、团队和入口策略不再参与评估，也不再提供管理入口。

### 在团队管理中集中管理审批

团队所有者和管理员可在**团队管理 → 工具审批**（`/app/team?tab=approvals`）中集中查看并修改当前团队可用且可编辑工具的审批策略。该页面只通过常规工具更新授权写入每个工具自身的策略，不会新增团队、站点、入口或工作流级别的审批层。其他成员的私有工具不会出现在列表中；自己的私有工具可以编辑；共享到本团队的工具在此只读，也不会显示所属团队的身份。逐行权限与只读原因见[团队管理 § 工具审批](../../user-guide/settings/team-settings.md#tool-approvals)。

工具执行审批仅由调用者确认。交互式 Agent 对话（包括已认证的飞书和微信智能体对话）会暂停并等待发起该调用的用户。使用 API 密钥发起的 Agent 运行会等待同一把密钥：该密钥可以读取并决定自己触发的待审执行。获取列表和直接调试不触发审批。

| 来源 | 工具审批 |
|------|----------|
| 登录后的 Agent 对话（网页、飞书、微信） | 暂停并等待发起调用的用户 |
| Agent API 密钥（`clou_...`） | 暂停并等待同一把密钥；其他密钥不能决定 |
| 嵌入组件、遗留渠道、定时任务 | 不等待；需要确认时以 `6510` 失败关闭 |
| 工作流（界面运行、工作流 API 密钥、嵌套调用） | 不创建审批关卡，也不等待 |

在 Agent 绑定的 MCP 服务器上开启**调用前确认**，即可要求每个子工具调用先确认。若只需审批部分子工具，在已保存的 MCP 定义上配置精确的调用者操作规则，例如 `tool:delete_task`。此类显式规则在 Agent 运行中生效，不要求同时打开 Agent 级开关；但子工具的 `allow` 规则不能放宽已开启的 Agent 确认开关。空策略不会自动推导为需要审批。策略中不能再指定个人用户或团队角色作为审批人。

Chat 在调用外部工具之前暂停，把审批卡片显示在发起该调用的用户面前。只有该调用者可以批准并恢复原调用一次，或拒绝并取消。参数、身份、连接版本和工具定义均与审批绑定；其他团队成员、团队管理员、超级管理员，以及同一用户名下的其他 API 密钥，都不能代为决定；拒绝、过期、撤销和运行停止也不会变成批准。

审批决定与策略变更都会记入审计日志。`approve_tool_execution` 与 `reject_tool_execution` 记录操作者（用户；密钥决策时为 API 密钥 id）、工具与执行标识、操作名、入口、运行、连接作用域、决定与结果。`update_tool_approval_policy` 记录审批设置确实发生变化的工具的前后策略。无权决定、已过期、已决定、绑定变化和幂等冲突等尝试记为失败决策。工具调用参数、凭据、API 密钥材料和审批人填写的理由都不会记录。审计写入为尽力而为：记录失败不会回滚决定或把已保存的策略变更报为失败。详见[审计日志管理 § 工具审批事件](../audit-logs/audit-log-management.md#tool-approval-events)。

使用 API 密钥的 Agent 客户端在整个运行中继续使用同一把密钥。运行进入 `waiting` 后，客户端可用该密钥调用 `GET /api/v1/tool-approvals` 列出待审关卡，或读取 `GET /api/v1/tool-executions/{execution_id}` 并提交 `POST /api/v1/tool-executions/{execution_id}/decision`（也可使用收件箱的决策接口）。密钥必须仍然有效、仍有权访问该 Agent（未关联任何 Agent 的密钥覆盖全部 Agent）且有权访问该次执行；其他密钥（即使属于同一用户）会收到 `6504 tool_approval_not_authorized`，且看不到该关卡。已撤销或过期的密钥返回 `401 invalid_api_key` / `api_key_expired`；失去 Agent 绑定后同样无权决定（`6504`），Agent 运行接口本身会返回 `403 api_key_no_agent_access`。批准后使用 `after_sequence` 重连运行流，即可收到同一 `tool_call_id` 的恢复 `tool_result`。

API Key 的列表结果只包含由同一把密钥提交的 AgentRun 所产生的执行记录。API Key 运行绑定功能上线前创建的旧记录（AgentRun 无密钥标识）出于安全考虑不会出现在列表中；若您仍持有其 execution id，可直接读取或审批——详情与决策会校验旧绑定，并在密钥冲突时拒绝。

嵌入组件、遗留渠道和定时任务仍属于非交互入口：当工具策略或 Agent 绑定要求确认时，调用会以 `6510 tool_approval_policy_configuration_required`（原因 `approval_audience_unavailable`）失败关闭，不产生副作用，也不等待决定。工作流不同：其工具调用根本不会创建审批关卡，无论是界面运行、工作流 API 密钥还是嵌套／子工作流，需要确认的工具都不会让工作流暂停。

确认卡显示待执行的操作、执行状态，以及有账号标签时的账号。展开“查看操作详情”可检查已隐藏敏感信息的参数；选择“允许执行”继续，选择“拒绝执行”则取消本次调用。

飞书和微信会向调用者发送脱敏确认消息。回复消息中完整的 `/approve <执行 UUID>` 或 `/reject <执行 UUID>`；每次决定只作用于该次调用。直接回复“同意”或“拒绝”等普通文字不能作出审批决定；普通回答仍用于 `ask_user`。

当模型在同一轮请求多个工具时，需要确认的调用会逐个显示。批准或拒绝后，运行按原顺序继续处理剩余调用；拒绝一个调用不会批准或取消其他调用。无需确认的调用按各自策略执行。

**遗留审批人配置失败关闭。** 工具策略中若包含 `user` 或 `team_role` 关卡（包括嵌套的 MCP 操作覆盖），会原样保留，但绝不会被当作调用者确认或放行。执行会在外部调用之前以 `6510 tool_approval_policy_external_audience_unsupported` 失败。工具编辑器会阻止保存此类策略，并提供一次性的**替换为调用者确认**操作；管理员也可以手动修改并重新保存为调用者确认，或选择不含外部审批人的明确允许/拒绝。工作流调用完全绕过审批，因此工具策略中的遗留外部关卡既不会让工作流暂停，也不会让工作流失败。升级会取消所有与遗留外部关卡关联且尚未开始的执行（`awaiting_approval` 或 `ready`，包括外部关卡已批准的任务）及其待处理关卡。同一次启动切换随后会唤醒所属等待运行：等待中的 AgentRun 会收到终态工具错误并重新排队，等待中的 WorkflowRun 停驻节点会失败，而不会一直挂起；用户需要重新发起运行。已经执行中或已进入终态的记录保持不动，供运维审计。启动切换会记录一条告警，列出已取消的执行、已取消的待处理关卡，以及仍带遗留关卡的工具数量；该切换可重复执行并在每次重启时重跑，因此滚动升级期间残留的旧 worker 无法为新任务取得外部批准——其尝试会在执行时失败关闭。已取消的执行保持终态，回滚也不会重新激活。已完成的历史记录仍可用于审计。嵌入、遗留渠道和定时入口从不弹出确认；若遗留外部关卡到达这些入口，同样会失败关闭，不会被绕过。

移除站点、团队和入口策略是另一次独立切换。已有策略行会保留用于审计，但不再被读取，相关管理接口和界面均已移除。任何尚未开始（`awaiting_approval` 或 `ready`）且保存的策略快照包含已移除策略层的执行，都会以 `cancel_reason: binding_changed` 取消，而不会在收窄后的纯工具级策略下继续运行；启动日志会记录取消数量，执行中和已进入终态的记录不受影响，这些执行之后也不能再被批准。取消提交后，切换会唤醒所属运行：待处理工具调用与已取消执行匹配的等待中 AgentRun 会收到终态 `binding_changed` 工具错误并被重新排队；等待中的 WorkflowRun 会收到恢复调度，使停驻节点以 `6507 tool_approval_binding_changed` 失败而不是一直挂起。唤醒会在每次启动时对等待中的运行做一次核对，因此提交与调度之间的崩溃或消息队列故障会在之后修复，重复执行是幂等的。已下线的策略表仍保留在原处，但应用不再读写。

MCP 调用名、参数和结果收纳在可展开的思考过程内，不再轮流替换思考栏标题；流式返回中尚未完整的 MCP 工具名不会作为调用事件发布。

**结果未知不会自动重试。** 如果外部副作用可能已经发生但结果未知（崩溃、连接丢失），执行会标记为 `outcome_unknown`。请核对外部系统并重新发起请求；平台不会静默重放调用。

服务器发起的 sampling 与 elicitation 同样等待人工处理：只有显式受众可以接受/拒绝，表单内容会按 schema 校验且不得收集凭据，URL elicitation 只允许配置的主机，会话丢失会把交互标记为 `connection_lost`，且不会重放外层调用。

## 资源订阅

使用 `GET /tools/{tool_id}/mcp/resources/subscribe?team_id=…&uri=…`，并设置 `Accept: text/event-stream`。打开流之前仍检查访问权限与连接身份；此直接能力浏览操作不触发执行审批。

- 事件：`subscription_opened`、`resource_updated`、`subscription_closed`。
- 关闭原因：`client_disconnected`、`ttl_expired`、`connection_lost`、`capability_unavailable`。
- 订阅仅在当前请求内有效。没有后台监听或持久订阅：断开或进程重启即结束，更新不会重放。
- 最多排队 100 条更新；客户端过慢时丢弃最旧更新。
- 生命周期受 `MCP_SUBSCRIPTION_TTL_SECONDS` 限制（默认 300 秒，最大 3600 秒）。

## 限制与运维

| 配置 | 默认 | 范围 | 用途 |
|------|------|------|------|
| `MCP_SUBSCRIPTION_TTL_SECONDS` | 300 | 10–3600 | 实时订阅最长存活时间 |
| `MCP_INTERACTION_TTL_SECONDS` | 300 | 10–900 | sampling/elicitation 最长等待时间，以及 MCP 回调窗口上限 |

协议预算对调用方固定：连接 10 秒，元数据列表/能力 20 秒，资源读取与提示词获取 30 秒。工具调用至少 60 秒，并随服务器配置的 `mcp_config.callback_timeout_seconds`（默认 120 秒，受交互 TTL 约束）增长。内容默认限制为单块 1,000,000 字节、总计 4,000,000 字节。

## 故障排查

| 现象 / 代码 | 含义 |
|-------------|------|
| `403 tool_access_denied` | 无消费团队访问权，或私有工具不可共享 |
| `409 tool_connection_required` | 缺少连接；先在连接管理中配置账号或登录，后台入口则需固定连接 |
| `409 tool_connection_default_required`（6403） | 有多个个人连接但没有默认；设置默认连接或明确固定账号 |
| `409 tool_connection_inactive` | 连接已撤销或需要重新认证；重新连接后重试 |
| `409 mcp_capability_unavailable` | 服务器未声明所需能力 |
| `504 mcp_request_timeout` | 协议预算超时 |
| `413 mcp_content_too_large` | 资源/提示词/结果超出内容预算 |
| `409 tool_execution_not_ready` | 待处理执行被拒绝、过期或已完成 |
| `401 invalid_api_key` / `401 api_key_expired` | 发起本次运行的 API 密钥已撤销或过期，不能再决定待审审批 |
| `403 api_key_no_agent_access` | 该密钥已失去当前 Agent 的访问范围 |
| `6504 tool_approval_not_authorized` | 您既不是发起本次执行的用户，也不是启动它的那把 API 密钥，不能代为确认 |
| `422 6510` | 保存仍包含遗留 `user`/`team_role` 审批人的工具策略会被拒绝；请替换为调用者确认 |
| `409 6510` | 工具审批策略格式错误，或仍使用遗留的个人/角色审批人；管理员需重新保存为调用者确认 |
| `409 6510`，原因 `approval_audience_unavailable` | 嵌入、遗留渠道或定时任务需要确认却无法等待；请改为交互式调用或调整工具策略 |
| `6434 tool_oauth_reauth_required` | OAuth 令牌已不可用，需重新授权 |
