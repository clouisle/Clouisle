# 知识库优化

优化知识库性能。

## 分块策略

Clouisle 按字符分块。默认值为 `chunk_size = 1000` 字符、`chunk_overlap = 100` 字符；UI 接受 100 到 2000 字符的块大小。这些是起点，不是按文档类型固定的预设。

| 起点 | 块大小 | 重叠 |
|------|--------|------|
| 普通 prose | 1000 字符 | 100 字符 |
| 简短问答 | 400-800 字符 | 50-100 字符 |
| 代码或结构化文本 | 800-1500 字符 | 100-200 字符 |

请使用代表性文档和检索质量进行调优；这些值是建议而非硬性默认值。

## 搜索参数

检索 API 使用 `top_k`、`score_threshold`，以及混合搜索的稠密/词法权重和 `rrf_k`。默认值为 `top_k = 5` 和 `score_threshold = 0.0`；知识库搜索没有 `max_tokens` 参数。上下文长度由聊天模型可用的 Token 预算决定。

- **top_k**：从 3-5 开始，只有召回不足时才增加
- **score_threshold**：从 0.0 开始，再用代表性评估集提高
- **search_mode**：针对语料比较 `vector`、`fulltext` 和 `hybrid`
- **重排序**：仅在有已授权重排序模型时启用，并用测量的质量/延迟调节候选数和阈值

## 何时重新处理

- 文档内容发生变化
- 分块设置或分隔符发生变化
- 需要显式重新处理/重新分块文档

现有知识库更换嵌入模型会被拒绝，因为其维度必须保持兼容。请创建替代知识库或使用显式迁移/重新处理流程；应用不会静默自动重建知识库索引。

## 评估

保留一组代表性查询，在更改设置前记录召回率、回答质量、延迟和成本。使用相同查询比较检索模式和重排序，不要依赖单个示例。
