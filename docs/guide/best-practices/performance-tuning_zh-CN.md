# 性能调优

性能优化技巧。

## 模型选择

从团队已启用且获授权的模型中选择。不要假设固定的 GPT-3.5/GPT-4 速度或质量排名；应在部署环境中用代表性提示测量延迟、回答质量、上下文容量和成本。

## 缓存策略

- 只缓存具有明确失效策略的数据。
- JWT 是主要会话机制；Redis 支持令牌黑名单和可选单会话状态，也用于 Celery 代理、速率限制和临时缓存。
- 除非提示词、模型、团队权限、工具和新鲜度要求都允许安全复用，否则不要添加全局 LLM 响应缓存。当前运行时缓存主要针对工作流定义和确定性节点结果，而非通用 LLM 响应。

## 数据库优化

- 为频繁过滤和连接使用的字段添加索引
- 使用适合部署规模的连接池
- 在修改 schema 或缓存设置前测量查询计划和检索延迟

## 工作流运行时

- 为每个循环设置上限。编辑器默认 10 次迭代，执行器上限为 1000 次。
- 对数组/对象批处理使用 Iteration 节点，并明确终止条件。
