# Agent vs Workflow

理解 Agent 和 Workflow 之间的区别。

## Agent

**对话式和自主**:
- 交互式聊天界面和多轮对话
- 模型可以根据上下文决定是否调用已配置工具
- 支持可选 RAG 模式（`off`、`auto`、`agentic`）和记忆

**使用场景**:
- 客服聊天机器人
- 个人助理
- 基于团队知识库的问答系统

## Workflow

**可视化图执行**:
- Workflow 是图的已发布版本，不一定是确定性的直线脚本
- 图可以包含入口和输出节点（用户输入、触发器、回答）、模型/媒体节点（LLM、Agent、媒体生成）、集成节点（工具、HTTP 请求、子工作流）、检索/文档节点（知识库检索、文档提取、文件转 URL）、转换节点（代码、模板、变量赋值/聚合、参数提取），以及控制流节点（条件、问题分类器、迭代/循环及其退出标记、暂停）
- 可以手动启动，也可以由 cron/webhook 触发
- 草稿可在调试模式中测试；已发布快照提供稳定的运行定义

**使用场景**:
- 数据处理流水线
- 自动化报告
- API 集成和定时任务

## 对比

| 特性 | Agent | Workflow |
|------|-------|----------|
| 界面 | 聊天 | 可视化图编辑器 |
| 执行 | 对话中的模型/工具决策 | 用户定义的图及模型、工具节点 |
| 控制 | 对话式、基于上下文 | 已发布图、触发器和节点配置 |
| 使用场景 | 交互式辅助 | 可重复的自动化与编排 |

需要开放式对话时选择 Agent；业务流程需要明确节点、输入、触发器和发布版本时选择 Workflow。
