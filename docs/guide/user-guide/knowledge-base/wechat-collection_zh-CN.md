# 微信互联

在**个人设置 → 微信互联**中授权微信连接。连接可以不启用用途，也可以用于知识库采集或单个智能体。**同一时间只有一个用途生效。**

1. **连接微信**——扫码并确认授权，无需先选择知识库或 Agent。
2. **选择用途**——选择“不做任何处理”“知识库采集”或“单个智能体”，配置后保存。未启用的用途配置会保留，但不会同时处理消息。

## 连接微信

1. 点击“微信扫码授权”，扫码并在微信中确认；如果微信要求验证码，在页面填写。
2. 授权完成后，连接列表会显示授权状态。可以保持连接但不启用任何用途；如需入库，再单独配置知识库采集。

**每个已验证的微信身份最多建立一个平台连接，多个人可以分别配置自己的连接，向同一个知识库采集。** 仅显示二维码不会创建连接；授权完成前，平台不能接收或回复该微信的消息。

## 配置采集（可选）

将当前用途设为“知识库采集”，然后选择：

- 一个已启用、有写权限的知识库。只读共享知识库不能作为目标。
- 按需选择目标团队已授权的视觉模型和语音识别模型。

保存后启用采集。选择“不启用”会停止采集，但不删除已保存的知识库与识别模型配置，也不断开微信。此后收到的消息会被忽略，不会暂存供以后处理。只能选择已有且有写权限的知识库。

每次提交保留贡献者和接收时的目标。仍有已接收内容待处理时，切换用途会被拒绝；等待处理结束后再切换。修改目标不会迁移已有文档。

## 改为使用 Agent 应用

选择“单个智能体”，从当前用户有权使用的已发布应用中选一个，填写必需的输入变量，按需选择语音识别模型后保存。此时知识库采集不生效；发送的链接、文件用于 Agent 对话，不会自动上传到知识库。选择“不做任何处理”仍会保留智能体配置。

每个连接使用独立会话，多轮消息默认继续该会话。更换 Agent 时隔离原有上下文；修改启动变量会创建新会话。可从个人设置中的 Agent 记录打开网页会话，仍需通过原有访问控制。

在微信发送 `/新对话`（或 `/new`）、`/停止`（`/stop`）、`/状态`（`/status`）、`/帮助`（`/help`）控制会话。普通消息按接收顺序处理，不会启动互相竞争的任务。Agent 追问时，后续回答用于恢复原任务，而不是新建一轮。`/新对话` 只在当前任务结束后生效；任务仍在运行时请先停止或等待完成。任务仍在运行或等待回答时，需先停止或等待完成，再切换用途。

Agent 使用扫码用户的真实身份，继续执行应用原有的模型、工具、知识库和额度限制。撤销权限或断开连接后拒绝继续执行或投递。普通任务在准备附件或提交运行前，会尝试发送一次去重的“🤔思考中...”提示；它表示已接收并开始准备处理，不代表任务完成。前一任务仍在运行时，后续消息使用已有的忙碌提示，不重复发送思考中提示；控制命令和追问回答保留各自的回复。微信会收到这些状态提示、最终答复和必要追问，不发送内部推理或工具调试内容。提示沿用相同的投递保护：结果不明确时不会盲目重发，微信不可用时不保证送达。

| 微信输入 | Agent 输入 |
| --- | --- |
| 文本 | 作为消息文本；上面的命令会被优先识别，不会启动任务。 |
| 图片 | 作为图片内容，需要 Agent 的聊天模型支持视觉。 |
| 文件 | 注册为会话内的私有 Asset，并沿用网页对话的普通文件输入。 |
| 语音 | 优先使用微信提供的转写；没有时用选定的语音识别模型转写下载的音频。 |
| 视频 | 转写音轨并抽样画面，需要 Agent 的模型支持。 |

附件附带的文字作为说明保留。超过 Agent 配置的大小或数量、扩展名不允许、模型无法识别的内容，都会以明确回复说明，不会静默丢弃。以“文件”形式收到的音频会像网页对话上传一样作为普通文件交给智能体，不会自动转写；语音消息才走上文的转写路径。

生成的图片、视频和文件通过微信原生媒体上传发送；生成的音频以文件形式发送，而不是语音气泡。投递内容只包括文本和已登记在会话内的 Asset，不会发送公开存储链接。个人的 Agent 记录会显示每条微信消息对应的运行状态和投递结果（排队中、发送中、微信已接受、发送失败、微信不可用未发送、已发送但结果未确认）。发送超时不会被盲目重发。

## 支持哪些内容？

| 内容 | 处理方式 |
| --- | --- |
| 纯文本 | 保存为 Markdown 文档，自动建立索引。 |
| 含 HTTP/HTTPS 链接的文本 | 分别抓取不同链接，保留附言。 |
| PDF、DOC/DOCX、XLS/XLSX、PPTX、TXT、Markdown、HTML、CSV、JSON | 下载解密后复用现有文档解析。文本格式需要 UTF-8；接受 PDF 格式不代表扫描版一定能提取文字。 |
| 图片 | 使用选定的团队视觉模型提取内容。 |
| 语音 | 优先使用微信提供的转写；没有转写时，下载音频并调用选定的语音识别模型。 |
| 音频文件 | 转换后使用选定的语音识别模型转写。 |
| 视频 | 有音轨时转写音轨，同时提取最多 12 个带时间标记的抽样画面。画面需要视觉模型，有音轨时还需要语音识别模型；不是逐帧完整视频理解。 |

一条消息中的各个附件分别处理，某项失败不会将其他附件一并判为失败。附件附带的文字作为说明保留，不额外生成一篇笔记。未知卡片和不支持的文件（包括 ZIP 压缩包）会明确显示失败。

公众号原生文章卡片是否提供可用链接取决于微信上游，目前不能保证。直接发送 URL 走文本链接路径。网页验证、访问限制也可能导致正文无法获取。

附件大小取“知识库文档上传配置”和 **100 MiB** 中较小的值。音视频需要可读时长，且不超过 **30 分钟**。未提取到有效内容、识别配置缺失或索引失败，都不会显示为入库成功。

## 查看结果与下载原件

“最近提交”按项显示已索引、重复、处理中和失败信息。原附件会保留；贡献者仍有目标知识库访问权限时，可以从提交记录下载原件。重复投递的消息不会重复创建文档；同一知识库内提取内容相同的提交会复用已完成文档，同时保留每次提交记录。

**只有索引完成才算入库成功。微信接口接受回复，不等于手机端一定已显示。** 对结果不明确的发送不会盲目重发；以平台内提交记录为准。

## 断开连接

“断开连接”停止接收新内容，待处理提交不再继续，已入库文档保留。重新连接需要再次扫码授权。失去写权限、目标删除或账户停用后拒绝采集；微信授权失效在平台页面显示，不能依赖微信发出提醒。不存在“未绑定用户先发消息，平台再提示绑定”的流程。

## 部署要求

先启动 API，由现有数据库初始化流程创建采集表，然后启动现有的 Celery worker **和** Beat 调度器。Beat 每三秒轮询一次微信，并交给 worker 落库；**不需要再单独部署微信接收进程**。

处理微信任务的 worker 需要访问 PostgreSQL、Redis，以及微信官方 iLink 和媒体 CDN 的 HTTPS 出站地址。消息接入（`app.tasks.wechat_agent.*`）与 Agent 运行共用 `agent` 队列，采集处理使用 `knowledge` 队列。Beat 每分钟恢复采集任务，每三秒重试 Agent 收件与未发出的回复。PostgreSQL 锁串行化处理；凭据、收件载荷、游标和回复上下文 token 都使用稳定的 `SECRET_KEY` 加密，API 与 worker 必须使用同一密钥。远程存储部署复用现有的内部上传网关，不需要上传目录。

Agent 模式还需要就绪的 Sandbox Worker，用于沙箱工具和已有会话工作区的检查点保存。该服务必须与普通 worker、Beat 一起保持运行；移除微信接收进程不等于移除沙箱依赖。macOS 本地开发请在仓库根目录运行 `backend/.venv/bin/python main.py sandbox-worker --local-dev -c 1`，使用包含 Bubblewrap 的 Linux 容器，不要通过关闭隔离来绕过缺少 `bwrap` 的问题。没有就绪的沙箱 worker 时，恢复／检查点保存可能超时，微信会提示 Agent 任务未完成；应检查对应 AgentRun 错误并恢复 worker 后再重试。

> [!IMPORTANT]
> 本次发布把采集目标和识别模型从连接记录移到独立的可选配置，并删除旧列。该切换**不向后兼容**：升级前必须停止仍在运行旧 schema 的进程，并把 API、Celery worker 和 Beat 作为同一步骤重启。

微信客户端支持情况、账号授权与部署网络准入由上游控制。正式开放前，需要在实际部署网络使用真实账号验收扫码、文章／卡片投递、附件下载和手机回复。

API 路径与请求字段见[英文指南的 API 表](wechat-collection.md#api)，全部使用当前用户 JWT，不能以通用 API Key 替代个人身份。
